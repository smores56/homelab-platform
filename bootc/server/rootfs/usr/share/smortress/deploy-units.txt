# Units a healthy host must have active, read by the post-boot gate
# (/usr/libexec/smortress-boot-gate) before it records a deployment as landed.
# The gate /fails the deploy if any line here is not active or is `failed`, so a
# unit listed wrongly rolls back every deployment -- the list is what "serving"
# means for this host, not every unit the image enables.
#
# A line is only valid for a unit that stays active on a healthy host: a oneshot
# with RemainAfterExit=yes, or a daemon. `smortress-tailscale-up.service` is not
# here for that reason: it carries
# ConditionPathExists=!/var/lib/homelab/tailscale-enrolled, so systemd skips it
# and it reads `inactive` on every host that has finished enrolling -- listing it
# would roll back every deploy on a healthy host. The tailnet is asserted through
# tailscaled instead.
#
# No unit that reads the tenant's plan is listed either: `smortress-tailscale-serve`
# exits 1 on a plan it cannot parse and `smortress-apps-quota` on an invalid plan
# or a quota it cannot apply, so either one in this list would let an app
# definition denylist the platform digest and roll back a healthy host -- the
# coupling the tenant prober exists to remove. Serve routes are checked by
# `smortress-apps-health` (base path per app), and a quota failure is journaled by
# the apply, which then refuses the revision.
#
# The deploy's own units are deliberately absent (the path, the drain, the poll
# and heartbeat timers): their secret is seeded by hand after the first landing
# (docs/manual-steps.md), and a missing one must page rather than roll the host
# back onto an image that cannot deploy.
#
# The web terminal is absent because it is not an image unit at all: it runs in
# the owner's user manager, whose unit ships with the dotfiles (SELinux refuses a
# system service an exec into a home binary). Its route is re-advertised at every
# boot by smortress-tailscale-serve, which is absent here for the reason above,
# and no prober reads svc:terminal -- the terminal is the one route without one.
